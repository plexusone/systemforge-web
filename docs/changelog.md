## [v0.8.0] - 2026-11-04

### Highlights

- A security release: navigation and redirects check their URLs, the API client keeps requests under `baseUrl` and drops cached data when the person or organization changes, and telemetry sends less personal data by default
- Packages: `@plexusone/api-client`, `auth`, `chat`, `pages`, `shell`, `telemetry` and `tenant` 0.3.0, `console` 0.2.0, `host` 0.5.0, `invites` 0.1.1 and `speech` 0.2.1; `design-tokens` and `ui` are unchanged

### Breaking

- `ApiClient` appends a request path to `baseUrl` instead of resolving it, so `/users` under `https://app.example.com/api` is `.../api/users`; a path with a scheme, host, backslash, control character or dot segment throws `TypeError`, and a relative `baseUrl` such as `/api` now works ([`42e31d9`](https://github.com/plexusone/systemforge-web/commit/42e31d9))
- `ProtectedRoute` roles and `usePermissions().hasRole` are checked in the organization `orgId` names, or the person's only membership; a person with several memberships and no `orgId` is refused ([`e4538e5`](https://github.com/plexusone/systemforge-web/commit/e4538e5))
- `AuthProvider.logout` keeps the person signed in and sets `error` when the server does not end the session, instead of showing them signed out ([`f4d7b9e`](https://github.com/plexusone/systemforge-web/commit/f4d7b9e))
- `LoginPage` follows `redirectUrl` only when it is on this site, and goes to `/` otherwise ([`a8ad27f`](https://github.com/plexusone/systemforge-web/commit/a8ad27f))
- `UserSettingsPage`'s profile tab is read-only unless `onSaveProfile` is given; Change avatar shows only with `onChangeAvatar` ([`e3490cb`](https://github.com/plexusone/systemforge-web/commit/e3490cb))
- Telemetry page views no longer send `document.title` or the referrer unless `collectTitle` or `collectReferrer` is set, and never a query string; clicks are named by `data-track`, `aria-label` or `id`, not element text; requests use `credentials: 'same-origin'` unless `credentials` says otherwise; the ProductGraph anonymous ID is kept in memory unless `persistAnonymousId` is set ([`654c028`](https://github.com/plexusone/systemforge-web/commit/654c028))
- `ChatComposer` focuses only with `autoFocus`; `ChatThread` takes `composer={false}` to leave out its own composer, which `ChatWidget` and `ChatEmbed` now do ([`2a22c1a`](https://github.com/plexusone/systemforge-web/commit/2a22c1a))
- `withConnection` returns `undefined` for a return address that is not http(s) or that would leave the site once rebuilt ([`7b81c1b`](https://github.com/plexusone/systemforge-web/commit/7b81c1b))
- `createHost` ignores `devSession` in a production build ([`743a24c`](https://github.com/plexusone/systemforge-web/commit/743a24c))
- `@plexusone/shell`, `tenant`, `pages`, `host` and `console` need `@plexusone/auth` 0.3.0 ([`3e135af`](https://github.com/plexusone/systemforge-web/commit/3e135af))

### Upgrade Guide

- Install the new versions together: the packages that depend on `@plexusone/auth` need 0.3.0
- Remove any `baseUrl` prefix you repeated in request paths, such as `/api/users` under `baseUrl: '/api'`, and encode IDs in paths with `encodeURIComponent`
- Pass `orgId` to `ProtectedRoute` and `hasRole` for role checks, or use `RequireRole` from `@plexusone/tenant`
- Pass `onSaveProfile` to `UserSettingsPage` to keep the profile editable
- Set `collectTitle`, `collectReferrer`, `credentials: 'include'` or `persistAnonymousId` (with consent) only if you need them; send ProductGraph events through a same-origin route that adds the API key
- Gate `devSession` on `import.meta.env.DEV`
- Run SystemForge v0.31.0 or later on the server: the org pages show admin controls only to owners, as that release enforces
