    TRD — Shell Foundations — Session, App Catalog, Organizations and Slots for Composed Apps¶

    Initiative: INIT-SYSTEMFORGEWEB-001 Repository: github.com/plexusone/systemforge-web

    Current state¶

    Package Has Missing for this initiative
    @plexusone/shell AppShell, Navbar, Sidebar, OrgSwitcher, UserMenu, Breadcrumbs, ShellContext Product switcher, slots, theme, brand config, controlled organization switching, tests
    @plexusone/auth AuthProvider, BFFClient (/bff/api/v1/users/me, /bff/auth/login with credentials, register, password, linked accounts) /bff/session, per-application roles, the app catalog, redirect sign-in
    @plexusone/tenant TenantProvider with the current organization in local storage Organization from the URL, switching through the application
    @plexusone/ui Avatar, DropdownMenu, Tooltip, Button, icons, Tailwind preset Compiled CSS for consumers without Tailwind

    All packages declare react ^19.0.0 as a peer dependency.

    Composition modes¶

    The shell supports two ways of composing applications. Everything in this initiative works in both.

    Single build Per host
    Applications Several AppModules in one front end (createHost({ apps })) Each AppModule built into its own front end, on its own host
    Moving between applications Client-side route change A link to another host, full page load
    Product switcher entries Registered applications The deployment's app catalog
    Session One BFF session One BFF session per host, one sign-in through the shared identity provider

    Both modes use the app contract below: an application is an AppModule, and a stack composes modules with a Shell through createHost.

    App contract and hosting¶

    A new package, @plexusone/host, separates three things that today live in each application:

    Piece Who provides it What it is
    The application Each cloud app (for example an agents app, a dashboards app) An AppModule: its pages and routes, navigation and top-bar contributions. No chrome, and no dependency on any stack
    The shell A stack (for example a suite's brand package), or DevShell A component implementing Shell: the chrome around an application
    The host A stack's web build, or an application's dev harness createHost({ app, shell }): the router, the organization in the URL and the session, with the shell around the application

    @plexusone/shell stays router-free and chrome-only; @plexusone/host depends on it, on @plexusone/auth, and on react-router as a peer.

    AppModule¶

    interface AppModule {
  id: string; // the application's ID in the app catalog and in roles
  name: string;
  routes: RouteObject[]; // the application's pages, relative to /orgs/:org
  navigation?: (ctx: AppContext) => NavSection[];
  profileItems?: (ctx: AppContext) => UserAction[];
  command?: ReactNode;
  actions?: ReactNode;
}

interface AppContext {
  organizationId: string;
  role?: string; // the role held in this application in that organization
  navigate: (path: string) => void; // relative to the organization
}

function useAppContext(): AppContext;
    • An application's pages read the organization and role from useAppContext() and never import a shell.
    • An application depends only on @plexusone/* and React. It does not know which stack hosts it.

    Shell¶

    interface ShellProps {
  app: AppModule;
  context: AppContext;
  onOrganizationChange: (organizationId: string) => void;
  children: ReactNode; // the application's routes
}
type Shell = (props: ShellProps) => ReactNode;

    A stack's shell is any component with these props. It renders its chrome (usually AppShell with its brand) and puts the application's navigation, slots and profile items in it. Swapping a stack's look is swapping its shell; the application is unchanged.

    createHost¶

    function createHost(options: {
  app: AppModule;
  shell?: Shell; // default DevShell
  sessionClient?: SessionClient; // default the BFF at /bff
}): ReactNode;
    • Provides the session, the router and AppContext.
    • / sends the person to the first organization they hold a role in this application in, or explains that they hold none.
    • /orgs/:org/* renders the application's routes inside the shell. An organization the person is not a member of renders "not found", as the APIs answer 404; a member without a role in this application sees "no access".
    • Signed-out visitors are sent to sign in through the BFF.

    DevShell¶

    A neutral shell in @plexusone/host, for running one application on its own: AppShell with the application's name as the brand, the product and organization switchers, the theme toggle and the profile menu.

    • With a fake session (devSession), it runs an application's interface with no backend: a person, memberships with roles, and a catalog, so the switchers and role-dependent controls can be exercised.
    • An application's dev harness is one line: createHost({ app, shell: DevShell }).

    Testing helper¶

    renderApp(app, { session, path, shell }) from @plexusone/host/testing renders an application inside createHost with a fixture session, for an application's own tests. A conformance check confirms an AppModule renders at /orgs/:org in DevShell without a stack.

    One build¶

    createHost({ apps: [...], shell }) composes several applications into one front end on one host, for a stack that serves them together. The product switcher then navigates on the client. This is the mode INIT-SYSTEMFORGE-001's reference host builds on.

    Session¶

    A SessionProvider reads /bff/session from the relying-party BFF:

    interface Session {
  authenticated: boolean;
  user?: SessionUser;
  apps: CatalogApp[]; // the deployment's application catalog
}
interface SessionUser {
  id: string; // principal ID
  name?: string;
  email?: string;
  avatarUrl?: string;
  memberships: Membership[];
}
interface Membership {
  organizationId: string; // the key; never a slug
  organizationName?: string;
  organizationSlug?: string; // display only
  role?: string; // organization role
  applications: Record<string, string>; // application ID -> role
}
interface CatalogApp {
  id: string;
  name: string;
  url: string;
  icon?: string;
}
    • Field names map from the BFF's JSON in one adapter, so the BFF's wire format does not leak into components.
    • Sign-in redirects to /bff/auth/login?return_to= or a provider route. Sign-out posts to /bff/auth/logout. No credentials pass through the shell.
    • The provider re-reads the session on focus and on an interval, and exposes onUnauthorized so an application can redirect.
    • @plexusone/auth's email-and-password flows stay available for deployments that use them; they are not the default.

    Product switcher¶

    function switcherApps(apps: CatalogApp[], self: CatalogApp, membership?: Membership): CatalogApp[];
    • Shows catalog applications in which the member holds a role for the current organization (membership.applications[app.id]).
    • The current application is always present and first, and marked aria-current="page".
    • With an empty catalog (local development) it shows the current application alone.
    • Entries for other hosts are links. In single-build mode the application can supply onNavigate for client-side routing.

    This rule is a pure function with unit tests, and the component renders it.

    Organization switcher¶

    • Controlled: value (organization ID) and onChange(organizationId). The application decides how the organization is carried, normally in the URL.
    • Lists the person's memberships by name, falling back to slug, then ID.
    • Hidden with one membership unless alwaysShow is set.
    • @plexusone/tenant's local-storage behavior remains as an opt-in uncontrolled mode.

    Slots¶

    AppShell and Navbar accept named slots:

    Slot Position Typical content
    brand Start Overrides the brand from configuration
    command After the product switcher Search or command bar
    actions Before the profile menu Product actions, notifications
    breadcrumbs Below or beside the bar Location within the application
    profileItems Inside the profile menu Application links

    A slot is ReactNode. The shell owns layout, spacing and responsive behavior; content is the application's.

    Chrome¶

    • Theme: light, dark and system, applied as the dark class on the root element (the class the design system's styles key on) with color-scheme, and persisted in local storage, wrapped so a storage failure falls back to system.
    • Profile menu: name, email, avatar, the current organization and the role held in this application, profileItems, and sign out. No default links to pages an application may not have.
    • Tooltips: icon-only controls use the ui tooltip and carry an accessible name.
    • Accessibility: menus close on Escape and outside click, focus returns to the trigger, and the switchers are keyboard operable.
    • Responsive: below a breakpoint the switcher and organization switcher collapse into one menu.
    • Navigation model: sidebar, top tabs, or none, chosen by the application.

    Brand configuration¶

    interface BrandConfig {
  name: string; // wordmark text
  logo?: ReactNode;
  tokens?: Partial<DesignTokens>; // from @plexusone/design-tokens
  productLabel?: string; // suffix such as "platform"
}

    A deployment publishes its brand as a small package that exports a BrandConfig and, optionally, a preconfigured shell component. The shell never names a deployment.

    Baseline¶

    Concern Choice
    React 19, as the packages already require
    Router Not required by the shell; onNavigate adapts to any router
    Styling Tailwind preset for Tailwind consumers, plus compiled CSS in @plexusone/shell/styles.css for others (decided in an ADR under this initiative)
    Tests Vitest and Testing Library, already configured at the workspace root
    Shared config Published TypeScript, lint and test presets, so an application adopts the baseline with one dependency

    Testing¶

    • Unit tests for switcherApps, the session adapter and the organization-label fallback.
    • Component tests for each switcher and the profile menu: rendering, keyboard use, Escape and outside click, aria-current.
    • A session fixture covering an empty catalog, one membership, several memberships and an application the person holds no role in.

    Compatibility¶

    • Existing exports keep working. OrgSwitcher's uncontrolled mode and UserMenu's actions stay, with the defaults changed to empty, which is noted in the changelog.
    • Field-name changes are confined to the new session types; existing @plexusone/auth types are not renamed.
